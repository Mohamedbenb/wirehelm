# Custota installation integration

On hold at the user's request. The sync patch remains applied; Custota startup is unresolved. Resume only when requested.

Custota 6.10 on the CP4A Pixel ran under `priv_app`, preventing access to Update Engine. Its generated `plat_seapp_contexts` was present in the module metadata but missing from OverlayFS MetaModule 1.3.1's separate content image. This matches [upstream issue 205](https://github.com/chenxiaolong/Custota/issues/205).

A narrow context-sync block is staged in `/data/adb/modules/meta-overlayfs/metamount.sh`, after the content image is mounted and before the existing mount binary runs. It copies only Custota's generated context file when Custota is enabled and its dedicated app-domain mapping is present. It retains the generated base-context records and file context, and logs a failure while continuing other module mounts. SELinux allow rules are unchanged.

Original handler: `/data/adb/wirehelm-custota-repair/metamount.sh.before`. Local copies and the prepared handler: ignored `build/custota-repair/`. Android shell syntax and a root-side copy/label preflight in an isolated probe directory passed. The approved reboot completed. The generated file is now mounted at `/system/etc/selinux/plat_seapp_contexts`, and its hash matches the module source and content-image copy. SELinux remains enforcing. Custota still cannot start: Zygote aborts during `selinux_android_setcontext` for UID 10332 before app code executes. The dedicated type names exist in the readable policy, but the exact rejection remains unresolved. This resembles the launch failure in [upstream issue 211](https://github.com/chenxiaolong/Custota/issues/211); do not apply the suggested broad system_app permission workaround. Automatic installation is off (default), and scheduled job 2 was verified as action CHECK before one forced attempt. No OTA installation was started. ADB went offline during investigation; reconnection was requested. The fix is incomplete.

Rollback: restore the backed-up handler to `/data/adb/modules/meta-overlayfs/metamount.sh`, remove only the added `system/etc/selinux/plat_seapp_contexts` file from the Custota content-image directory if present, and reboot. Do not remove the module image or another module's content. A metamodule update may replace this local handler modification; review its mount behavior before reapplying. Future firmware boots regenerate contexts before the sync, avoiding a frozen context file from an older OTA.
