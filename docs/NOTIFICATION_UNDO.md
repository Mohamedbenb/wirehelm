The feature saves an enabled switch, independent Show Undo button and Shake to Undo switches, and Gentle/Standard/Firm strength. Button defaults on for older saved configurations. With button off, no Undo window is created; shake alone can restore during grace. An enabled feature requires at least one restoration method. If a requested shake-only sensor cannot register, the swipe falls through to native dismissal instead of holding an unusable grace. It stays enabled across screen off, lock/unlock and SystemUI restarts. Dismissal and Undo work in the drawer and on an AWAKE lock screen. Turning the screen off finishes the pending grace and removes its banner/sensor listener; it does not disable the feature. No screen-off wake lock, continuous sensor or periodic alarm. Android retains its original lock-screen visibility/redaction and action authentication.

An individual swipe retains the original entry/action tokens in memory for five seconds, hides it through the native pipeline, and offers a generic Undo banner (no message text). Undo reveals that original; timeout invokes stock dismissal. No copied/reposted notification, archive or message/reply logging. Other server-based observers can still count it during grace. Abrupt SystemUI death may reveal an original whose server cancellation was not committed. The final asynchronous client-to-server cancellation race remains native, not a cross-process atomic transaction.

## Eligibility and native ownership

Individual messages and ORIGINAL summary notifications in app groups and Android autogroups are supported. A summary owns its original summary entry and the children selected by native NotifCollection.shouldAutoDismissChildren. Protected children remain native. Arrival, row replacement, bubble/policy state or generation changes invalidate the operation. Native summaries without an original notification entry remain stock; Clear all remains stock. Last-child companion summary identity is captured using native fetchSummaryToDismiss. A summary may legitimately have no rendered row (WhatsApp); entry/generation ownership still applies, and only a real extant view is reset. Arrival, update, cancellation, regrouping or row replacement invalidates the pending grace without canceling replacement content.

Messenger bubbles remain enabled. No bubble handling runs during grace. Timeout delegates to native dismissNotification/BubbleCoordinator/WM Shell, which may hide a shade entry while retaining its bubble/server record. Undo never manufactures a bubble or invokes its action. Changed bubble metadata/suppression state invalidates grace. An already-running native dismissal remains stock.

Heads-up and pinned-state exclusions were REMOVED at the user's explicit request. Do not restore them from old feasibility notes.

Clear all, media, ordinary ongoing/foreground services, calls/alarms/full-screen intents, active reply/IME, inaccessible/replaced rows and another concrete Android user remain stock. UserHandle.ALL (-1) is a global notification, not another user. Wireless debugging is a narrow ongoing exception: android/id62/channelDEVELOPER_IMPORTANT, and only if its native dismissibility provider permits clearing. No-clear/FGS protection stays intact. ## Persistent configuration and recovery

JSON key notificationUndo is a string containing enabled:boolean, shake:boolean, button:boolean (defaulttrue) and sensitivity:integer0..2. NotificationUndoSettings validates it; IndicatorSettings carries an immutable snapshot; LocalCustomization saves/publishes it through the existing protected configuration channel. applyNotificationUndo owns only this feature and preserves the ring/other choices. Stale saves from unrelated feature pages cannot turn Undo off. It participates in root backend feature activation and recovery disable. A runtime fault suspends handling; it does not silently cancel the saved choice. An explicit configuration revision permits recovery; ordinary heartbeats do not reset the five-second lease.

One-time migration records a concrete setting on first262 initialization. Existing users with sample posts or held-notification evidence migrate enabled, unless recovery is paused. Fresh users stay off. Once the setting exists, later samples/process restarts cannot re-enable an opt-out. Migration adds a new preference field without altering unrelated choices. The five-minute expiry and exported trial-start broadcast/bridge endpoint are removed. App UI exposes persistent switches, with samples/raw diagnostics collapsed below them.

## Gesture and window lifecycle

The accelerometer is registered only while an actual five-second pending original exists. Two acceleration peaks120..900ms apart, a low-force rearm and250ms initial warmup reduce inadvertent triggers. A captured pending token prevents stale sensor callbacks from undoing a newer dismissal. Undo, expiry, cancellation/update, settings change, screen off, recovery pause and user switch clear the listener and owned window. A missing sensor leaves the Undo button available. No haptic is added. The small trusted SystemUI banner can appear over keyguard and displays only the generic dismissal label. Undo never unlocks the device or executes a message action.

## Group commit adapter

BubbleCoordinator reads NotificationEntry.getAttachedNotifChildren during native dismissal. Filtering a pending group can detach its rows before that read. NotificationUndoCommitContext therefore captures genuine original attached-child lists, verifies their active group membership and exposes copies only for those entries, on the owning thread, inside the synchronous native commit call. A single exact getter hook returns native behavior at every other time. It preserves ArrayList shape required by this firmware's R8 code, and is cleared in finally even on failure. No UI hierarchy or native bubble state is patched to simulate membership. No new notification/action token is synthesized.
